# REQ-001 — Active User Retrieval

## Requirement

The system shall provide a way to retrieve only active users.

## Business Rule

A user is considered active when the `active` field is `true`.

## Expected Behaviour

- Active users must be included.
- Inactive users must not be included.
- The original user collection must not be modified.

## Testing Expectations

The implementation should have tests covering:

- Active users
- Inactive users
- Mixed active/inactive users
- Empty user collection

## New Requirement

The system shall also provide a way to retrieve only inactive users.

## New Business Rule

A user is considered inactive when the `active` field is `false`.

## Expected Behaviour for Inactive Users

- Inactive users must be included.
- Active users must not be included.
- The original user collection must not be modified.

## Testing Expectations for Inactive Users

The implementation should have tests covering:

- Inactive users
- Active users
- Mixed active/inactive users
- Empty user collection
- Original collection remains unchanged

## Additional Requirement

The system shall provide a way to count the number of active users.

## Expected Behaviour

- Return the number of users where `active` is `true`.
- Return `0` for an empty collection.
- Do not modify the original user collection.

## Testing Expectations

The implementation should have tests covering:

- Multiple active users
- No active users
- Mixed active/inactive users
- Empty user collection
- Original collection remains unchanged
